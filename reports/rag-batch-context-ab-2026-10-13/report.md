# 按批次定向补充 RAG：开发集 A/B

日期：2026-10-13  
规则集：`official-v3-2026-10-12`（46 条规则）  
模型：`qwen3.7-plus`，thinking=false，batch=4，concurrency=8  
检索：BM25 + text-embedding-v4/1024 + RRF  
样本：5 条已经暴露的 provisional 开发案例，每种配置各运行 1 次

本报告是工程对照，不是正式 P3 效果评估。样本没有专家 gold，次数不足以证明准确率或生产时延。

## 对照项

- `global`：旧方式。全局召回条文尝试复制到每个规则批次，再受 30,000 字符条文预算及 90,000 字符完整 Prompt 预算收缩。
- `targeted`：新方式。全局召回后，用当前批次直接法条的 BM25 相似度及已有条文向量中心进行二次 RRF；候选必须同时处于文案排名和批次排名前列，每批最多补充 8 条、8,000 字符。
- 两组都检查全部 46 条规则，直接条文、支持条文、证据校验、引用白名单和聚合逻辑不变。

## 结果

违规、局部材料、提示注入和改写科普四例在两组中结论一致且符合开发预期。原教育反例在两组中都因 `Evidence does not occur in the specified source` 导致一个规则批次失败；targeted 没有引入新的失败，但也没有解决这个既有模型输出问题。

## 长材料复验

使用此前触发 `context_budget_exceeded` 的完整“慈铭体检+保险”文本，targeted 真实调用结果：

- `completed / non_compliant`，0 错误，46 条规则均进入台账；
- 全局召回 210 条，13 个规则批次；
- 最大单批 Prompt 44,442 字符，低于此前 workflow 1.3 同材料记录的 54,529；
- 38.391 秒，19 次模型尝试，prompt tokens 156,546；
- trace_id：`68b51f73-b8d0-4f3f-a332-a69980f6b99c`。

单次长材料时延高于此前记录，说明模型服务波动和输出量仍主导端到端时延，不能把一次运行的差异归因于 RAG。最大 Prompt 缩小约 18.5%，且没有再出现上下文预算错误。

## 结论

当前小样本支持启用 `targeted` 作为默认工程配置：它保持相同的开发案例通过数，并减少 Prompt、token、可选条文重复和结构修复次数。现有证据只证明成本和上下文规模改善，尚不能证明审核准确率提升。P3 仍需在人工核对的 20 条开发集和 40 条冻结测试集上比较违规召回、误报、引用准确率和三态 Macro-F1。
