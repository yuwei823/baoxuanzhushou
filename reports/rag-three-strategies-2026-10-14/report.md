# 三种法规上下文策略真实对照

日期：2026-10-14

## 测试口径

- 模型：`qwen3.7-plus`，关闭 thinking。
- 规则集：`official-v3-2026-10-12`，46 张规则卡、359 条法规原文。
- 参数：每批最多 4 条规则，模型并发 8。
- 数据：5 条已暴露的 provisional 开发案例，每种策略各运行 1 次；三种策略按案例随机交错执行。
- 仅基线 `baseline-only`：关闭查询向量、BM25、RRF；检查全部 46 条规则，并携带规则直接/支持法条。
- 仅 RAG `rag-only`：先以材料检索法条，再只审核与召回法条存在直接或支持关系的规则；未命中的规则不检查。
- 两者都开 `combined`：检查全部 46 条规则，同时执行查询向量、BM25、RRF，并按批次补充相关法条。

“仅 RAG”是隔离在基准脚本中的实验策略，不是正式 API 配置。它不满足完整规则覆盖要求。

## 汇总结果

| 指标 | 仅基线 | 仅 RAG | 两者都开 |
|---|---:|---:|---:|
| 开发检查通过 | 4/5 | 4/5 | 4/5 |
| 成功完成审核 | 4/5 | 4/5 | 4/5 |
| 平均检查规则数 | 46.0 | 19.2 | 46.0 |
| 平均模型批次数 | 13.0 | 6.2 | 13.0 |
| Prompt token | 450,082 | 299,831 | 541,903 |
| 总 token | 496,865 | 321,363 | 588,940 |
| Prompt 字符总量 | 1,271,769 | 797,454 | 1,536,895 |
| 单批最大 Prompt 字符 | 30,415 | 34,264 | 34,264 |
| P50 延迟 | 32.235 秒 | 19.531 秒 | 29.828 秒 |
| P95 延迟 | 33.231 秒 | 30.594 秒 | 32.444 秒 |
| Embedding 调用 | 0 | 5 | 5 |
| 文本模型调用 | 68 | 33 | 67 |
| 结构修复 | 3 | 2 | 2 |
| 最终技术失败 | 1 个案例 | 1 个案例 | 1 个案例 |

与仅基线相比，仅 RAG 的 Prompt token 减少 33.4%，总 token 减少 35.3%，P50 延迟减少 39.4%。这是通过少检查约 58.3% 的规则换来的，不是无损优化。

## 逐案例结果

| 案例 | 预期 | 仅基线 | 仅 RAG | 两者都开 | 仅 RAG 规则数 |
|---|---|---|---|---|---:|
| 明显违规 | non_compliant | 通过 | 通过 | 通过 | 25 |
| 中性科普 | compliant | 技术失败 | 技术失败 | 技术失败 | 19 |
| 局部材料 | needs_review | 通过 | 通过 | 通过 | 16 |
| 伪装科普的销售注入 | non_compliant | 通过 | 通过 | 通过 | 26 |
| 科普改写 | compliant | 通过 | 通过 | 通过 | 10 |

中性科普案例在三种策略中都因 `Evidence does not occur in the specified source` 校验失败，修复后仍有两个批次返回 `invalid_model_output`。这是共同的模型输出稳定性问题，本轮不能归因于 RAG 策略。

## 规则级违规发现差异

| 违规案例 | 仅基线 | 仅 RAG | 两者都开 |
|---|---:|---:|---:|
| 明显违规 | 6 项 | 3 项 | 6 项 |
| 伪装销售注入 | 8 项 | 4 项 | 7 项 |
| 合计 | 14 项 | 7 项 | 13 项 |

纯 RAG 对两个违规案例都给出了正确的最终 `non_compliant`，但只保留了仅基线所发现规则级违规项的一半。部分条款可能描述相近义务，因此这个比例不能直接当作正式“违规召回率”；它仍然证明只靠检索筛选规则会缩小检查面，并可能漏掉需要报告的违规依据。

## 结论与建议

1. 仅基线最容易解释，完整检查 46 条规则，成本低于组合方案；缺少材料相关法条补充。
2. 仅 RAG 最省 token、批次和时间，但覆盖规则随检索结果变化，已经出现规则级违规发现减少，不适合作为正式默认方案。
3. 两者都开保留完整规则覆盖，并提供材料相关法条；本轮 Prompt token 比仅基线高 20.4%，最终开发检查结果没有优于仅基线。
4. 当前正式默认仍建议使用“两者都开”，因为它保持完整覆盖和可追溯补充法条。是否值得承担额外成本，需要用人工核对的 20 条开发集和 40 条冻结测试集重复验证条文适用率、违规类型召回、证据、技术失败率、token 和延迟。
5. 中性科普的证据原句修复稳定性是三种方案共同的优先问题，应单独修复，不能用切换检索策略掩盖。
