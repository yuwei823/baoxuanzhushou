# 纯文本 RAG 实施方案（待实施）

日期：2026-10-11。用户明确要求使用 RAG；本文为方案，尚未切换线上检索流程，不代表已完成。

## 目标与现状

当前 BM25 已检索并记录 ID，但实际模型上下文主要来自规则卡关联原文。改造目标是让召回的法规内容真正决定候选规则和证据上下文，同时保留独立的规则覆盖检查，避免“没检索到就合规”。图片识别暂缓。

## 一、离线索引

只读已发布 official-v1-2026-10-11 快照，使用用户本地文件的核对原文；不自行下载替换法规。保险法继续暂缓，不混入当前索引。

以条文为父对象，长条文按实际款/项生成子块，不机械截断例外。每块保留 chunk_id、article_id、父级、版本、原文定位和哈希。检索文本可拼接文档标题、章节、条号、原文；规则卡解释可建独立检索字段，但不能冒充条文原文。

建立两路索引：中文分词 BM25；text-embedding-v4、1024 维向量。当前 172 条文规模可使用本地 NumPy 归一化矩阵做余弦检索，不必引入向量数据库或 Agent 框架。模型与维度已配置，真实 Embedding 调用尚需探测。

调用 OpenAI 兼容 embeddings 接口；按当前官方约束每批最多 10 个文本，并校验每条 token 上限。来源：[向量接口文档](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)。索引记录 ruleset_hash、embedding_model、dimensions、chunker_version、检索文本哈希。变更时构建新索引，校验完后原子切换；失败不得启用半成品。新法规沿 P0 候选审阅/发布流程，再触发索引构建。已发布法律快照不被索引写入修改。

## 二、在线审核流程

1. 文本校验、分段并保留原始 Unicode 位置；所有段落参与查询，不只取前 512 字。原句查询优先，保留否定、限定与引用语境；首版不额外调用 LLM 改写查询。
2. 每段分别检索向量 Top 8 与 BM25 Top 8，使用 RRF 融合去重。这里的 8 是初始开发参数，不是经评估证实的最佳值。
3. 将命中块关联到规则卡，形成候选检查；每个候选补齐父条、定义、适用范围、关联条件及例外。对完整材料的披露义务，走独立必查清单，不能依赖违规关键词召回。
4. 对规则全集建立适用性台账。只有已知条件明确不满足的规则才可标记不适用；未知主体/渠道/完整性等保留复核项，必要时补检索。轻量预筛不负责最终违规裁决，也不能只凭低检索分数排除规则。
5. 上下文构建器按 rule_id 聚合“输入证据 + 召回原文 + 必须补齐原文 + 适用条件/例外”。记录 retrieved / mandatory / parent / definition 等加入原因，去重后按预算分批；完整条文放不下则分批或报未完成，不静默截断。
6. 文本模型仅依据该批原文逐规则输出结构化判断。额外召回的条文若没有核对过的规则映射，仅作上下文或复核依据，不让模型临时发明可执行规则。
7. 程序校验条件、证据、引用 ID、规则覆盖；引用必须同时属于已发布快照、本次提供原文及该规则合法引用集合。原文由知识库回填，再确定性聚合三态。

这构成 Retrieve → Augment → Generate 的真实链路。必查规则补齐仍会占用上下文，不能承诺引入 RAG 后一定更快；应分别测量检索、适用性、判定耗时及 token。

## 三、Prompt 与故障策略

保留现有否定/教育反例、保证与非保证利益区分、来源隔离、缺失披露完整性要求、Schema 和校验。新增检索来源与上下文加入原因说明；向量相似度不当作合规置信度。Prompt 固定版本，开发样例与测试集分开。

Embedding 调用、排队及重试纳入整体 150 秒预算与调用次数记录，和判定共享并发限制。缓存键包含文本哈希、模型、维度与索引版本；默认不落盘原始用户输入。索引离线构建单独记录用量。

明确配置 retrieval_mode=hybrid。向量失败时默认返回技术错误；如果后续实现显式 BM25 降级模式，必须在结果中标注实际模式及失败原因，不能将降级结果算作 hybrid 验收。

## 四、实施顺序与交付

| 步骤 | 产物 | 验收 |
|---|---|---|
| R1 索引 | Embedding 适配、build-index CLI、本地索引及 manifest | 真实接口成功；条目/维度/哈希一致；索引与快照版本绑定 |
| R2 检索 | 分段查询、双路召回、RRF、retrieval trace | 改写/否定/尾部信息能检索；所有召回 ID 可追溯 |
| R3 上下文 | 候选映射、独立必查、父条例外补齐、预算分批 | 召回原文实际进入模型消息；无丢失规则、无跨版本引用 |
| R4 端到端 | 文本 API/CLI、引用校验、三态及失败报告 | 违规/反例/需复核及故障注入通过；无视觉调用 |
| R5 对照评估 | 开发集及冻结测试的指标报告 | 同模型/规则集/数据，对比 BM25 RAG 与 hybrid RAG；报告条文召回、违规召回、误报、复核率、延迟、token |

先完成 R1–R4 的工程闭环。R5 证明效果后才宣称检索或 Prompt 优化有效；不把三个演示案例当正式评估。暂不增加 reranker，只有开发集证明排序问题再单独评估。

现有可复用：已发布知识库、规则卡、Schema、模型客户端、校验器、聚合器、API 和页面。主要新增：向量适配/索引、混合检索、上下文构建及检索评估；无需推倒重写。
