# 初审模式替换为 decision-model-preview：时间与成本估算

评估日期：2026-10-18  
评估口径：保持当前初审装箱方式——RAG 平均选中 19.2 条规则，每批最多 4 条，平均 6.2 个判定批次，并发上限 8。

## 1. 先说结论

从模型形态看，`decision-model-preview` 很可能显著缩短初审等待时间，并把模型调用的边际费用降到接近零；但当前不能把 Token Plan 个人版密钥接入本项目的 FastAPI 后端。

阿里云当前规则明确：

- `decision-model-preview` 限时免费，调用暂不消耗 Credits；
- 目前只通过 Token Plan 个人版提供；
- 个人版只允许在编程工具和智能体工具中交互式使用；
- 不得用于自动化脚本、自定义应用后端或非交互式批量调用。

因此，下列数字只能作为技术容量估算，不能作为当前线上部署报价。正式实施前必须获得阿里云书面确认的后端可用产品、商业授权或正式百炼模型计费入口。

成本复算：

```text
输入：59,966 × ¥2 / 1,000,000  = ¥0.1199
输出： 4,306 × ¥8 / 1,000,000  = ¥0.0344
查询向量：约 27.4 × ¥0.5 / 1,000,000 = ¥0.000014
原价合计：约 ¥0.1543 / 条
当前限时八折：qwen 部分约 ¥0.1234 / 条
```

当前 `batch-flow` 页面采用原价口径，便于避免把短期活动价当作长期成本。阿里云模型价格页目前标注 qwen3.7-plus 实时调用限时八折；优惠可调整。这 5 条只是已暴露的 provisional 开发案例，能用于工程量级估算，不能代表正式业务平均值。

## 3. 保持原装箱后的 decision 调用量

如果仍按每批最多 4 条规则装箱，并为每条规则提出“适用性”和“是否违规”两个 Choice 问题：

| 项目 | 平均值 |
|---|---:|
| 规则数 | 19.2 |
| decision 请求数 | 6.2 次/材料 |
| question 数 | 38.4 个/材料 |
| 每批 question | 最多 8 个 |
| 查询 Embedding | 1 次/材料 |

请求数量不会明显减少，主要收益来自：decision 返回短结构，不再生成每条规则的长 reason、证据和条件说明。

## 4. 运行时间估算

官方未公布该模型的稳定延迟或 SLA，当前项目也没有可用于后端基准的合规 Token Plan 密钥。因此只能给出工程区间，不能写成实测值。

### 4.1 纯 decision 初筛

如果 6～8 个批次允许像当前一样并发发送：

| 阶段 | 估计耗时 |
|---|---:|
| Embedding + 本地 BM25/RRF | 0.2～0.8 秒 |
| 6.2 个 decision 批次并发 | 2～8 秒 |
| 结果映射与聚合 | <0.2 秒 |
| 估计端到端 P50 | 约 3～8 秒 |
| 估计端到端 P95 | 约 5～15 秒 |

相对当前 P50 19.5 秒，理论上可能缩短约 60%～85%。这个判断依赖服务是否允许 8 路并发、单批 8 个 questions 的实际延迟及限流，必须用 D0 探针验证。

### 4.2 推荐的“decision 初筛 + qwen 证据复核”

现有 qwen 每个初审批次的平均费用约为：

```text
原价：¥0.154 / 6.2 ≈ ¥0.025 / 批
当前限时八折：¥0.123 / 6.2 ≈ ¥0.020 / 批
```

因此可以按需要复核的 qwen 批次数估算：

| qwen 复核批次 | 估计总时间 | 估计 qwen 费用/条 |
|---:|---:|---:|
| 0 批 | 3～8 秒 | 接近 ¥0 |
| 1 批 | 6～15 秒 | 原价约 ¥0.025；当前活动价约 ¥0.020 |
| 2 批 | 8～20 秒 | 原价约 ¥0.050；当前活动价约 ¥0.040 |
| 全部 6.2 批 | 接近当前 19～31 秒 | 原价约 ¥0.154；当前活动价约 ¥0.123 |

这里的单批成本按现有均值线性折算。实际值会受材料长度、同一材料在不同复核批次中的重复、法条长度、结构修复和输出量影响。

比较现实的目标是：大多数中性材料只走 decision；存在违规候选或不确定项时，再用 1～2 个 qwen 批次生成证据和引用。按原价口径，单条审核的 qwen 成本可能落在 ¥0.025～¥0.050，较当前初审降低约 68%～84%。这必须通过真实样本确认，不能用假设直接对外报价。

## 5. decision 模型费用

截至评估日，官方页面写明 `decision-model-preview` 限时免费，不消耗 Token Plan Credits。因此：

- 已有合规可用套餐时，decision 调用边际费用当前为 ¥0；
- 仍需支付查询向量的极小费用，按现有样本约 ¥0.000014/条；
- 若没有套餐，Token Plan Lite 当前限时 ¥39/月、原价 ¥60/月；
- 按 1,000 条/月简单摊销，¥39 套餐约 ¥0.039/条，但这不构成后端使用授权；
- 免费活动和套餐价格可能调整，不能写进长期产品报价。

## 7. 开发工期估算

在获得允许用于应用后端的正式接口之后：

| 工作 | 预计人日 |
|---|---:|
| 真实接口探针、权限和限制确认 | 0.5～1 |
| 独立客户端、Schema、错误和重试 | 1 |
| 规则卡到 questions/criteria 编译 | 1～1.5 |
| service 初审路由、qwen 复核与回退 | 1～1.5 |
| 单元/集成测试与影子日志 | 1～1.5 |
| 20 条开发集校准和报告 | 1～2 |
| 合计至可评审版本 | 5.5～8.5 人日 |

如果还要完成 40 条冻结测试集的人工标注、复核和正式效果报告，另需约 3～5 人日，取决于合规人员能否及时完成标签确认。

## 8. 建议决策

1. 暂不把 Token Plan 个人版密钥写入本地或云端 FastAPI 配置。
2. 向阿里云确认是否有允许自定义后端调用的企业版、团队版或正式按量计费入口，以及 `decision-model-preview` 是否包含在内。
3. 获得允许后先跑 5 条探针，只测延迟、批量 questions、并发和响应契约。
4. 再运行影子模式，验证实际 qwen 复核批次能否控制在平均 1～2 批。
5. 只有成本、时延和违规召回同时达标，才切换初审；完全模式保持现状。
