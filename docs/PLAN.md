## 1. 目标与执行规则

交付本地可运行的文本／有序多图审核 demo，包含百炼真实调用、规则及证据追溯、三态结论、部分失败处理、网页与 JSON 导出、评估报告和交接材料。

- 按 P0 → P1 → P2 → P3 推进，以阶段验收结果控制进入下一阶段，不预设未经确认的完成日期。
- 按用户后续指示采用 hybrid 文本 RAG，BM25 保留为评估基线；必查覆盖是必做项，不能以召回替代覆盖。
- 每项任务具备稳定 ID、依赖、产物和验收证据。代码写完不等于验证完成。
- checkbox 仅在对应验收通过且证据已记录后勾选；受阻项保留未勾选，并登记阻塞原因。
- 每轮在 HANDOFF.md 追加修改文件、执行命令、结果、实际版本、问题及下一步；更新本计划的任务状态。
- 无 Key 时可继续 mock 和离线工作，但真实调用里程碑仍未完成。人工标注未完成时保留 provisional，不伪称可信 gold。
- 本计划不要求多 Agent，不默认部署或发布，不进入 SPEC 排除的生产能力。
